## Ecobot 시스템 아키텍처 및 흐름도 문서

GitHub 최신 상태 기준의 Ecobot 시스템 아키텍처 문서이며, 텍스트로 기술되었던 구조 및 처리 흐름을 시각적인 다이어그램(이미지 형태로 렌더링되는 Mermaid)으로 변환하여 포함하였습니다.

---

## 1. 개요

Ecobot은 지역별(서울·천안·부산 남구·제주·인천 미추홀구 등) 분리배출 가이드와 환경 법령을 근거로 답변하는 RAG 기반 챗봇입니다. FastAPI 백엔드, MySQL, FAISS 벡터 검색, Gemini/OpenAI LLM으로 구성됩니다.

---

## 2. 전체 구조 다이어그램

시스템의 전체적인 구성 요소와 호출 관계를 시각화한 다이어그램입니다.

```mermaid
graph TD
    Browser[브라우저] -->|API 요청| Router[API 라우터 / app/routers/]
    Eval[평가 스크립트 / evals/run_eval.py] -.->|API를 거치지 않고 직접 호출| RAG[RAG 파이프라인]
    
    subgraph FastAPI 백엔드 서버
        Router --> RAG
    end
    
    RAG --> MySQL[(MySQL)]
    RAG --> FAISS[FAISS 인덱스 / LLM API]

```

---

## 3. 계층별 구조

### 3-1. API 라우터 (`app/routers/`)



* **`api.py`**: 인증(`/api/auth/*`, `/api/me`), 문서 CRUD 처리


* **`rag.py`**: 챗봇(`/api/chat`), 대화방 복원(`/api/chat/sessions`), 인덱스 관리, 인기 질문 처리


* **`admin.py`**: 관리자 대시보드 통계·문서 관리·업로드 기능



### 3-2. 서비스 계층 (`app/services/`)



* **`chunk_service.py`**: 문서 청킹 (법령: 조문 단위, 가이드: 품목 단위)


* **`embedding_service.py`**: 텍스트를 벡터로 변환하며 `local`/`gemini`/`openai`/`hash` 백엔드 전환 및 디스크 캐시 지원


* **`vector_store_service.py`**: FAISS 인덱스 생성·저장·검색 및 차원 불일치 검증 수행


* **`gemini_service.py`**: LLM 호출(`LLM_BACKEND`로 Gemini/OpenAI 전환), `<answer>`/`<tip>` 태그 파싱


* **`rag_service.py`**: 지역/공통/법령 자리 배분(`_apply_quota`)을 수행하는 오케스트레이터


* **`auth_service.py`**: 회원가입(`register_user`) 및 로그인 검증(`authenticate_user`) 처리


* **`document_service.py`**: 문서 CRUD 로직, 순환 참조 방지 검증(`check_circular_dependency`) 포함


* **`tools_service.py`**: 파일 텍스트 추출 함수(`extract_text_from_file`) 제공



### 3-3. 평가 (`evals/`)



* **`qa_set.json`**: 정답셋 (질문·모범답안·필수/금지 키워드·지역 구분)


* **`run_eval.py`**: API를 거치지 않고 `rag_service`를 직접 호출하여 답변 품질을 측정하는 평가 스크립트



### 3-4. 데이터 저장



* **MySQL**: `users`, `documents`, `chat_logs`, `chat_messages`, `question_clusters` 테이블 관리


* **FAISS**: `data/indexes/index.faiss` 및 `chunks.json` 활용


* **원문 데이터**: `data/laws/`, `data/guides/` 경로에 법령 및 가이드 원문 적재

## 4. 데이터베이스 스키마 (ERD)

```mermaid
erDiagram
  USERS ||--o{ DOCUMENTS : owns
  USERS ||--o{ CHAT_LOGS : asks
  USERS ||--o{ CHAT_MESSAGES : sends
  QUESTION_CLUSTERS ||--o{ CHAT_LOGS : groups

  USERS {
    int id PK
    string email
    string hashed_password
    string display_name
    boolean is_active
  }
  DOCUMENTS {
    int id PK
    int owner_id FK
    string title
    longtext content
    longtext content_text
    longtext summary
    string source_type
    string source_url
    string region
    int parent_id FK
  }
  CHAT_LOGS {
    int id PK
    int user_id FK
    text question
    string region
    boolean has_answer
    int cluster_id FK
  }
  CHAT_MESSAGES {
    int id PK
    int owner_id FK
    string session_id
    string region
    string role
    longtext content

  }
  QUESTION_CLUSTERS {
```

## 5. 요청 처리 흐름 (`/api/chat`) 다이어그램

브라우저에서 사용자의 질문이 입력되고 응답이 반환되기까지의 처리 과정을 시각화한 순서도입니다.

```mermaid
sequenceDiagram
    autonumber
    actor Browser as 브라우저
    participant API as rag.py (/api/chat)
    participant RAG as rag_service.ask()
    participant Gemini as gemini_service
    participant DB as MySQL / FAISS

    Browser->>API: {question, region, session_id} 전송[cite: 1]
    API->>DB: 대화 기록 조회 및 chat_messages 저장[cite: 1]
    API->>RAG: rag_service.ask() 호출[cite: 1]
    RAG->>DB: 지역 필터 및 쿼터 배분 기반 벡터 검색[cite: 1]
    alt 근거 자료 없음
        RAG-->>API: 즉시 "찾을 수 없음" 반환[cite: 1]
    else 근거 자료 있음
        RAG->>Gemini: answer_with_context() 호출[cite: 1]
        Gemini-->>RAG: <answer>/<tip> 태그 형식 답변 생성[cite: 1]
    end
    RAG->>DB: 답변 저장(chat_messages) 및 통계 기록(chat_logs, question_clusters)[cite: 1]
    RAG-->>Browser: {answer, tip, source, sources} 응답[cite: 1]

```

## 6. 인증 및 보안 흐름 다이어그램

JWT와 httpOnly 쿠키를 활용하여 보안을 유지하는 인증 처리 흐름입니다.

```mermaid
sequenceDiagram
    autonumber
    actor User as 사용자
    participant Client as 브라우저
    participant AuthAPI as 인증 API (/api/auth)
    participant Security as core/security.py
    participant DB as MySQL (users)

    User->>Client: 로그인 정보 입력 (이메일/비밀번호)[cite: 1]
    Client->>AuthAPI: POST /api/auth/login[cite: 1]
    AuthAPI->>DB: 사용자 정보 조회[cite: 1]
    AuthAPI->>Security: 비밀번호 검증 (bcrypt 해시 비교)[cite: 1]
    Security-->>AuthAPI: 검증 성공[cite: 1]
    AuthAPI-->>Client: JWT 발급 및 httpOnly 쿠키(access_token) 응답[cite: 1]

    Note over Client,AuthAPI: 이후 인증이 필요한 모든 요청[cite: 1]

    Client->>AuthAPI: API 요청 (쿠키에 JWT 포함)[cite: 1]
    AuthAPI->>Security: get_current_user()를 통한 쿠키 JWT 추출 및 검증(python-jose)[cite: 1]
    Security-->>AuthAPI: 유효한 User 객체 의존성 주입[cite: 1]
    AuthAPI-->>Client: 정상 데이터 응답[cite: 1]

    Client->>AuthAPI: POST /api/auth/logout[cite: 1]
    AuthAPI-->>Client: 쿠키 삭제 응답[cite: 1]

```
